# 四種記憶詳解

---

## 1. Episodic Memory（情景記憶）

### 用途

記錄當前 session 中依序發生的事件。相當於 agent 的「工作記憶」——只屬於這個 session，session 結束後會被壓縮寫入 Semantic Memory。

### 何時寫入

每次 tool call 的開始與結束都會寫入：

```python
# Tool 開始
await episodic.add(EpisodicEntry(
    event="tool_call",
    tool="read_file",
    arguments={"path": "doc/SUMMARY.md"},
    session_id=self.session_id,
))

# Tool 結果
await episodic.add(EpisodicEntry(
    event="tool_result",
    tool="read_file",
    result="4869 chars",  # 截斷至 SMAL
    duration=0.12,
    session_id=self.session_id,
))
```

### 資料結構

```python
@dataclass
class EpisodicEntry:
    id: int | None
    session_id: str
    event: str              # "tool_call" | "tool_result" | "error"
    tool: str | None        # 工具名稱（event=tool_* 時）
    arguments: str | None   # 參數摘要（截斷）
    result: str | None      # 結果摘要（SMAL 截斷）
    duration: float | None  # 耗時（秒）
    created_at: str         # ISO timestamp
```

### Session 結束時的處理

```
Session 結束
    ↓
所有 EpisodicEntry 送入 LLM 提取 FACT
    ↓
每個 FACT upsert 至 SemanticMemory
    ↓
原始 EpisodicEntry 刪除（SQLite VACUUM reclaim 空間）
```

FACT 格式：
```
FACT: [session:abc123] 用戶要求建立 doc/ 目錄，已建立 doc/SUMMARY.md
```

## 2. Semantic Memory（語義記憶）

### 用途

儲存關於世界、程式碼庫、專案、協作者的事實。長期保存，可 upsert（後寫覆蓋先寫），可驗證失效。

### API

```python
# 寫入（upsert by key）
await semantic.upsert(
    key="project:db_schema",
    value="資料庫使用 SQLite，WAL 模式，路徑 ~/.loom/memory.db",
    confidence=0.9,
)

# 讀取
entry = await semantic.get("project:db_schema")
# → SemanticEntry(key="project:db_schema", value=..., confidence=0.9, ...)

# 刪除
await semantic.delete("project:db_schema")

# 列出最近
recent = await semantic.list_recent(limit=20)

# 搜尋
results = await semantic.search("SQLite WAL")
```

### Anti-pattern 寫入（v0.2.5.1 Counter-factual Reflection）

工具執行失敗時，LLM 反思產生的 Anti-pattern 以特殊 key 格式寫入：

```python
# Key 格式：skill:<tool_name>:anti_pattern:<timestamp>
await semantic.upsert(
    key=f"skill:{tool_name}:anti_pattern:{timestamp}",
    value="[Anti-pattern] 嘗試在 Windows 路徑使用 Unix 路徑分隔符導致 read_file 失敗；下次應先檢查 OS",
    confidence=0.8,
    source="reflection",
)
```

此類 key 可被 `recall("anti_pattern <tool>")` 召回，agent 在下次執行同類工具前會看到警告。

### 資料結構

```python
@dataclass
class SemanticEntry:
    id: int | None
    key: str
    value: str
    confidence: float           # 0.0 - 1.0，預設 0.8
    source: str | None          # "session:xxx" | "agent:xxx" | "manual" | "reflection"
    created_at: str
    updated_at: str
    embedding: str | None       # Phase 5：向量（JSON 字串）
```

### Trust Tier 與 Governance（v0.2.9.0）

所有 Semantic Memory 寫入現在都通過 `MemoryGovernor.governed_upsert()`，每個 entry 的 `source` 字串決定其信任等級與 confidence floor：

| Source 模式 | Tier | 信心值下限 |
|------------|------|-----------|
| `"manual"`, `"user"` | `user_explicit` | 1.0 |
| `"tool:*"` | `tool_verified` | 0.9 |
| `"memorize"` | `agent_memorize` | 0.85 |
| `"session:*"` | `session_compress` | 0.8 |
| `"counter_factual:*"` | `counter_factual` | 0.75 |
| `"skill_eval:*"` | `agent_inferred` | 0.7 |
| `"dreaming"` | `dreaming` | 0.6 |
| `"fetch:*"`, `"web:*"` | `external` | 0.5 |

當寫入的 entry 與既有 entry 衝突時，Trust Tier 較高者勝出；相同 tier 則取最新（SUPERSEDE）。詳見 [08b-Memory-Governance.md](08b-Memory-Governance.md)。

### Phase 5：衝突追蹤（5F-1）

當 upsert 時發現 key 已存在且 value 不同：

```python
# 舊值寫入 metadata.history[]
entry.metadata["history"].append({
    "old_value": old_value,
    "source": old_source,
    "overwritten_at": old_updated_at,
})

# 保留最近 3 筆歷史
entry.metadata["history"] = entry.metadata["history"][-3:]
```

## 3. Procedural Memory（程序記憶）

### 用途

儲存「如何做」的技能——有效的 prompt patterns、成功的重構策略、經過驗證的工作流程。每個技能是一個 **Skill Genome**。

### Skill Genome 結構

```python
@dataclass
class SkillGenome:
    id: str                     # 唯一識別，"refactor_extract_function"
    version: int                # 版本號，每次更新 +1
    confidence: float           # EMA confidence，0.0-1.0
    usage_count: int            # 累積使用次數
    success_rate: float        # 歷史成功率
    parent_skill: str | None   # 父技能（用於技能繼承）
    deprecation_threshold: float = 0.3  # 低於此值自動廢棄
    tags: list[str]             # ["refactor", "python", "function"]
    body: str                   # 技能主體（有效時的 prompt 或描述）
    created_at: str
    updated_at: str
```

### Confidence 更新

`SkillGenome.confidence` 由 `SkillOutcomeTracker` 根據 task 結果的 quality_score（1-5）以 EMA 計算，不在 SkillGenome 上直接寫入。

> 舊版 `SkillGenome.record_outcome(success: bool)` 的二元成功/失敗模型已移除（Quest D Phase 1.C / audit-A）。詳見 [10-Skill-Genome.md](10-Skill-Genome.md) §SkillOutcomeTracker。

### 自動廢棄

`SkillGenome.is_deprecated` 是 read-only property：當 `usage_count >= MIN_SAMPLES_BEFORE_DEPRECATION` 且 `confidence <= deprecation_threshold` 時返回 True。`ProceduralMemory.list_active()` 透過 SQL 查詢自動排除，DB row 本身不被修改。

## 4. Relational Triples（關係三元組）— 走 SemanticMemory 的橋接視圖

> **#451 phase B 起**：原本獨立的 ``RelationalMemory`` 子系統已退役。三
> 元組 ``(subject, predicate, object)`` 現在以 ``rel:{subject}::{predicate}``
> 的鍵儲存在 ``semantic_entries``，由 ``loom/core/memory/relational_bridge.py``
> 提供 ``RelationalEntry`` dataclass + ``upsert_triple`` /
> ``get_triple`` / ``query_triples`` / ``delete_triple`` 助手；agent 透過
> 唯一的 ``recall`` 讀取入口讀回，沒有獨立的 ``query_relations`` 工具。

### 用途

儲存三元組（subject, predicate, object）形式的關係性事實：

```
subject,          predicate,    object
"user",           "prefers",   "concise answers"
"project:loom",   "uses",      "SQLite WAL"
"task:deploy",    "depends_on","task:build"
```

適合記錄用戶偏好、系統關係、任務依賴等。

### Anti-pattern 三元組（v0.2.5.1）

反事實反思產生的 Anti-pattern 三元組透過 bridge 寫入語意儲存：

```python
from loom.core.memory.relational_bridge import RelationalEntry, upsert_triple

await upsert_triple(semantic, RelationalEntry(
    subject=f"skill:{tool_name}",
    predicate="has_anti_pattern",
    object="使用 Unix 路徑分隔符處理 Windows 路徑",
    confidence=0.8,
))

await upsert_triple(semantic, RelationalEntry(
    subject="loom-self",
    predicate=f"should_avoid:{tool_name}",
    object="在 Windows 環境下使用 / 作為路徑分隔符",
    confidence=0.9,
))
```

`MemoryIndex` 在 session 開始時透過 ``query_triples(semantic, subject="loom-self")`` 讀取 Self-Portrait，讓 agent 知道自己過去應避免什麼。

### Self-Portrait 三元組（v0.2.5.3 → Issue #120 PR 1）

`loom-self` 主詞的觀察三元組原由 `SelfReflectionPlugin` 在 session 結束時寫入。Issue #120 PR 1 起改由 `TaskReflector`（`loom/core/cognition/task_reflector.py`）在每次結構化診斷後以 post-hook 的形式呼叫 `run_self_reflection` 寫入：

```python
# 三種 predicate 类型
(loom-self, tends_to, <observation>)      # 傾向性觀察
(loom-self, should_avoid, <observation>)    # 應避免行為
(loom-self, discovered, <observation>)       # 新發現
```

### API

```python
from loom.core.memory.relational_bridge import (
    RelationalEntry, upsert_triple, get_triple,
    query_triples, delete_triple,
)

# 寫入三元組（鍵為 rel:user::prefers）
await upsert_triple(semantic, RelationalEntry(
    subject="user",
    predicate="prefers",
    object="繁體中文回答",
    confidence=1.0,
))

# 點查（subject + predicate）
got = await get_triple(semantic, "user", "prefers")

# 列出某主詞的所有 predicate
prefs = await query_triples(semantic, subject="user")

# 篩 predicate
all_prefs = await query_triples(semantic, predicate="prefers")

# 全列（給 MemoryIndex 統計用）
everything = await query_triples(semantic)

# 刪除
await delete_triple(semantic, "user", "prefers")
```

Agent 在對話中讀取三元組就直接呼叫 ``recall(query)``——命中的 ``rel:*``
鍵會以 ``type="relational"`` 出現在結果裡，不需要切換 verb。

### 資料結構

```python
@dataclass
class RelationalEntry:                 # loom/core/memory/relational_bridge.py
    subject:   str
    predicate: str
    object:    str
    confidence: float = 1.0
    source:    str = "agent"
    metadata:  dict[str, Any] = field(default_factory=dict)
    id:        str = field(default_factory=lambda: str(uuid.uuid4()))
    created_at: datetime
    updated_at: datetime
    domain:    str = DEFAULT_DOMAIN
    temporal:  str = DEFAULT_TEMPORAL
    last_accessed_at: datetime | None = None
```

實際儲存為 ``SemanticEntry``：``key=f"rel:{subject}::{predicate}"``、
``value=f"{subject} {predicate} {object}"``（BM25/embedding 都可自然召
回），authoritative S/P/O 留在 ``metadata`` 供 round-trip 解碼。

### 與工具整合

```python
# relate 工具（GUARDED）— #451 phase B 寫入語意儲存
@loom.tool(trust_level=TrustLevel.GUARDED)
async def relate(subject, predicate, obj, confidence=1.0) -> str:
    from loom.core.memory.relational_bridge import RelationalEntry, upsert_triple
    await upsert_triple(semantic_memory, RelationalEntry(
        subject=subject, predicate=predicate, object=obj,
        confidence=confidence, source="agent",
    ))
    return f"已記住：{subject} {predicate} {obj}"

# 讀取統一走 recall，不再有 query_relations 工具。
```

## 主記憶的 Schema 對照

> #451 phase B：relational 不再是獨立 schema，三元組以 ``rel:*`` 鍵存
> 入 ``semantic_entries``，原本獨立的欄位都來自 SemanticEntry。

| 欄位 | Episodic | Semantic | Procedural |
|------|----------|----------|------------|
| id | ✅ | ✅ | ✅ |
| key/name | session_id+seq | key（含 ``rel:*`` 橋接行） | id |
| content/value | event+tool+result | value | body |
| confidence | — | ✅ | ✅ |
| source | ✅ | ✅ | — |
| timestamp | created_at | created/updated_at | created/updated_at |
| parent | — | — | parent_skill |
| metadata | ✅ | ✅（含 subject/predicate/object for rel:*） | ✅ |
