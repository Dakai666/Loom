## 1. 定案方向

絲絲是自己的記憶的使用者。回顧、取捨、排序、準備與放手，本身就是使用；不以 DK 是否追問或稱讚來決定她的記憶活動有沒有價值。

這次升級以整併與精練為優先，每個新概念先找現有結構承接。契約測試通過後直接進主 agent 實戰，不等待 2026-11-16，不以長期 shadow mode 或正式 A/B 設施作為前提。既有蒸餾觀察可繼續，但不得阻塞本案。

## 2. 沿用、替換與刪除

| 需求 | 使用現有結構／本版變更 |
|---|---|
| 身份、關注、未完活動與整理時機 | circadian 的 `evening_closure`／`check_in`；不新增 curator runtime 或排程 |
| 長線興趣／先於來源存在的主題 | PursuitStore；不新增興趣資料庫 |
| 長期保留／放手 | `temporal=milestone`／降回 `recent`；不新增 retain／release 旗標，不修改 confidence |
| 準備／擱置 | 唯一新增一張小表：key、stance（prepared／shelved）、理由、value hash、expires_at |
| 編輯準備清單 | 一個整份重寫的編輯工具，清單最多 5 條；不造一組動詞工具 |
| 記錄與人工檢視 | 既有 tool call、ledger／session_log 及原始輸出；不新增活動表、自評欄或證據分類系統 |
| 主動浮現 | Hook G 改讀準備清單，取代原本 project×milestone top-3；Hook A 不動 |
| 自由夢 | DK 已決定退役 `offline_dreaming`；完整入口收斂另列後續項 |

新功能啟用時，Hook G 只使用準備清單，清單為空就保持安靜；不在清單空白時偷偷跑回舊 top-3。整個功能明確關閉時，才走原本 Hook G，作為回復機制。兩種模式互斥，不並存兩條注入路徑。

r0 的獨立 messages／快照執行環境、lease、持久待辦、30 分鐘／4 小時觸發、活動紀錄表、scanned／curated／applied 欄、last_curated_at、retain、新 pulse type、事件時間新語意與 provenance 回填全部移出首版。

## 3. A：#634 的最小修正

主責 Codex，CC review。A merge 後再開 B+C。

1. `recall_period` 將 `session_id` 傳給 semantic 的 `list_between`，使用現有 `source=session:<id>` 精確篩選。無 session_id 時維持原有行為，不做 schema migration 或來源回填。
2. `include_sessions=true` 時，session metadata 清單也依指定 id 篩選；episodic／messages 沿用既有 scope，避免同一回傳混入別的 session。
3. 僅 `recall_period` 對真正回傳的 semantic facts 補 `mark_accessed`，空結果不蓋章。只列出或掃描資料的底層維護 API 不因此變成讀取蓋章入口。`get_fact` 無產品呼叫點且不是 agent 工具，本次維持原行為；保留或退役留待後續入口清理。
4. 工具描述明示：概念問題用 recall，時間窗與已知 session 事件用 recall_period；保留現有 updated_at 的時間窗語意，不在首版新增事件時間模型。
5. 無法從既有 source 辨識的 memorize／其他來源視為未知；跨 session 合併後的 survivor 只保有一個 source，本版不保證恢復所有歷史 session 歸屬。這是已知覆蓋邊界，不包裝成完整事件回放。

測試契約：有／無 session 篩選、相似 id 不誤配、各回傳群組 scope 一致、返回項目蓋章但未返回項目不變、背景 list 不蓋章、既有時間窗與工具輸出不退步。依 PR #636 review，list_between 在 SQL 的 LIMIT 前排除 redirect stub，避免佔名額或被 period recall 蓋章；不改 get_fact／resolve_redirect 的解析語意。

先用原 issue 的真實問法走工具取得證據。工具描述可能改善選擇，但「改描述必然解掉昨晚那次失敗」仍需實測，不先當作結論。

## 4. B+C：主體整理與 Hook G 一起交付

主責 CC，Codex review。寫入端與讀取端共用一張表，由同一人整合 session／工具接線。

### 4.1 整理發生在自己的既有活動中

在 evening_closure 回顧當日、在 check_in 接續長線關注；主體自行決定要讀什麼、準備什麼、晉升什麼、放下什麼。沿用既有自主 turn 與權限，不新增通用 curator 身份。

既有 turn 共用 session 脈絡，由 `_turn_lock` 序列化；正確性依賴既有排隊與鎖，不是新開一份 messages 達成隔離。整合作業需測到整理與互動 turn 不並行、不偷偷增加另一個 scheduler。

check_in 的關注從既有 pursuits 讀取，不把靜態課題清單當完整興趣範圍。PursuitStore 是可復用的儲存／編輯介面，不需要複製其內容到新表。

正常 agent 在自主 turn 有意識呼叫 recall／recall_period，仍算讀取；單純系統盤點不算。沒有專用背景掃描器，就不額外造一組不蓋章查詢 API。

整理報告不應自動轉成新 semantic facts，但現行 auto extractor 會壓縮 autonomy session，這項不變式目前尚未有機制保障。CC 在 B+C 加入契約測試及對應實作，防止整理流水帳被重新抽成 0.8 的 session facts；不能只在 prompt 寫一句要求就宣稱已避免自我抽取循環。

### 4.2 單一清單的寫入契約

- 整份替換最多 5 條，空清單合法；一個 agent 的表不讀寫另一個 agent 的清單。
- prepared 可供 Hook G 使用；shelved 只是不主動準備，原 fact 仍能透過一般 recall 找到。
- 寫入與讀取都以來源 value hash 檢查版本；過期、來源不見、內容改寫或 redirect 需要重新審視時不投放舊判斷。第一版可直接略過失效項目，不另造修訂追蹤系統。
- 清單更新須原子完成，驗證失敗不留下半份清單；現有 tool／ledger 輸出保留理由與差異，供原始案例檢視。
- 清單移除或到期只取消準備，不自動降級 fact 的 temporal；「不準備說」和「不值得長期保留」分開。
- 興趣與保留不改 fact value、confidence 或 domain。晉升／降級沿用既有記憶編輯入口；若需在同一編輯工具接住，先列明輸入／更新契約，不增加一組獨立動詞。
- 放手只撤回這個整理流程自己做的晉升；不得把原本由使用者或其他流程建立的 milestone 一併降級。利用既有 metadata／工具紀錄辨識責任，無法辨識時維持原狀。
- 現有 half-life 契約保留：self／user／project 的 milestone 為 ∞，knowledge 為 365 天；dreaming source 仍受 21 天上限。不能為了「保留」改來源或 domain 繞過此限制。自由夢已決定退役，首版不新增夢來源的特殊永久保留路徑。
- 單一編輯工具要如何展現清單與支援整份修改，由 B+C 契約定案；不把新 read/edit 動詞家族當前置。

### 4.3 Hook G 的單一路徑

直接替換 Hook G 選取來源，沿用既有 PulseRecord／注入路徑與 memory_meta，不新增 pulse type。Hook A 的內容、節流及矛盾語意保持獨立。

turn 開頭 drain 的內容提供給絲絲當次判斷；若適合對話，可在同一回應末尾自然接續。不能強制附帶「對了」，不在串流完成後另跑模型拼接。

現有 once-per-key 只能限制相同 key，不能保證不同 key 合計每 session 最多一次。首版需用既有 session／memory_meta 表達整個 session 的主動 brief 配額，與 Hook A 分開；同一候選另做 key 去重。不建立新配額資料表。

必須區別「發出一次 brief」與「主模型實際說出一次補充」：前者可以由 gate 確定限制，後者不能只靠 prompt 就宣稱硬保證。首版以每 session 最多一份主動 brief 為可測契約，prompt 要求不要反覆補充；若實戰仍重複說，再修具體行為。

目前 Hook G 是 session start 準備、turn 開頭 drain；在同一長 session 的 evening_closure 才寫入的新清單，不能假設已被舊的 start hook 看見。B+C 必須選清楚並測到：重用該 hook 於後續 turn 讀取未投遞清單，或明確只在下個 session 生效。優先重用現有 turn 邊界且受同一配額約束，不新增平行 loop。

測試先 red 再實作：隔離、完整替換／空清單、value hash／到期失效、milestone 升降邊界、來源不被改寫、Hook G 換源、session 整體配額與 Hook A 獨立、新清單跨 turn／session 接續、停用回到原本行為。保留既有聊天串流與記憶測試。

### 4.4 B+C as-built（與本節契約的差異）

- **儲存**：沒有新增資料表。準備清單是既有 `memory_meta` 的一列（key `attention.list`，值為 JSON 陣列）。整份替換＝寫一列，天然原子；per-agent DB 天然隔離。
- **單一工具**：`memory_attend`（SAFE）。不帶參數＝顯示清單與各項來源狀態（live／expired／changed／merged／gone）；`items` 整份替換（≤5，`[]` 清空）；`keep`／`let_go` 升降 milestone。一次寫入先整份驗證，任何一項不合法就整筆不變（含 keep/let_go）。輸出附差異（`+`／`-`／`~`、kept、let go），留在既有 action_records／ledger。
- **晉升責任**：keep 在 fact metadata 標 `kept_by="attention"`＋`kept_at`；已是 milestone 的 fact 不接手（回報「already milestone」），let_go 只降回自己標過的。不改 value、confidence、domain、source、`updated_at`。
- **Hook G**：`[memory.attention] enabled = true` 時，`MemoryPulse` 只讀清單裡 `prepared`、未過期、value hash 相符、未被合併的項目；清單空就安靜，不退回 top-3。`false` 時是原本的 Hook G，工具也不註冊。仍只在 session start 執行：**每 session 至多一份 brief 由結構保證**，不另建配額；session 中途寫的清單於下一個 session 生效。circadian 的 daily-life session 在夜間收束後關閉、dawn 新開，因此 `evening_closure` 寫下的清單會在隔天第一個 session 出現。
- **不自我抽取**：`memory_attend` 的 tool trace 不寫入 episodic（`records_episodic_trace`），session 壓縮讀不到它；action_records／session_log 照常保留。整理過程中呼叫的 `recall` 等工具照舊進 episodic——那是既有行為，不在本次範圍。
- **沒有線索的記憶的入口**（DK 2026-10-22 追加）：recall／recall_period 都要先有線索，沒想到的記憶不會自己回來。`memory_attend` 不帶參數查看時，附上隨機 5 條 30 天以上沒被讀過的事實（排除 stub、dreaming 來源、已在清單上的），並標示來源（memorize／session／agent…），讓她分得出手寫與機器抽取。這是退役自由夢後，把其中唯一有價值的「偶遇」收回現有工具：抽到之後由主體判斷，不自動寫入任何東西。抽樣不蓋讀取章。
- **Hook G 投放不蓋讀取章**：brief 是系統帶到眼前，不是 agent 主動讀；長期保留走 keep。

## 6. 直接實戰驗收

T0 是新功能在主 agent 啟用並實際完成一次 evening_closure 整理的時間，不是寫 spec 的日期。

| 時點 | 必交證據 | 卡住時 |
|---|---|---|
| T0 當次 | 版本／設定、真實整理輸出、準備／擱置與晉升取捨、清單持久化、下一次使用／恢復 | 接線未通就修，不稱為進入觀察 |
| T0 + 24h 內 | 第一份案例：看了什麼、為什麼保留或放下、如何接續、成本與失敗 | 零活動時定位 anchor 未觸發／工具未授權／空輸入／未接 Hook G；當日手動走真實流程補證 |
| 前 3 個適用機會或 T0 + 72h，先到者 | 實際活動與來源；明確保留、修正或停掉哪一段 | 無自然機會可用真實歷史材料受控重跑，但標明受控案例 |
| T0 + 7d 內 | 第一輪結論與下一個具體變更 | 不自動延長成一個月觀察；無效就改或關閉無效部分 |

必備情境：

1. DK 沒有要求記住、也不需要回應：絲絲仍整理自己的關注，跨 session 留下可理解的取捨。
2. 回到自己的閱讀／研究／未完活動，能接續或修訂先前取捨。合理地維持原判斷也可以，不強迫每輪產出。
3. 擱置仍可 recall／恢復；原本 milestone 不被誤降；失效 hash 不投放。
4. 相關時出現，無關時安靜；Hook A 不被新配額吞掉。
5. #634 的 session 問法與 recall_period 蓋章符合 A 的範圍；get_fact 不在本次修改內。

使用既有原始工具輸出與實際活動判斷，不建立 agent 自評表。不以整理次數、總筆數下降或 never-accessed 比例改善單獨證明價值。沒有 DK 追問不記為失敗，更不據此遺忘。

舊蒸餾快照保留；記錄本次計數修正、升級與自由夢退役時間，不把之後的全部變化歸因給舊蒸餾設計。
